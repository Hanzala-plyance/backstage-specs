# Backstage 0.1.0 foundation — develop candidate

Status: **blocked from release promotion**. Feature: integrate-backstage-foundation.
The product intent is a reliable venue appliance; this increment connects branding,
song preparation/library, and native controller setup. Reservations, authorization,
two-bay operations, and central management remain planned.

## Automated evidence

Evidence and final commits are recorded in the active change handoff. Local source,
service, and controller checks do not substitute for a Unity game build.

## Required before stage

- Build with Unity 6000.3.5f2, initialized pinned submodule, and restored packages.
- Record the exact tested commit, artifact location/checksum, and build log.
- Run automated checks successfully against the candidate.

## Required before main

- Play an installed converted song in the actual Backstage build.
- Physically verify supported guitar/MIDI routes; do not claim the incompatible
  Xbox Riffmaster bridge is supported.
- Verify clean installation, service/game restart, device disconnect/reconnect,
  and library recovery. Verify public branding in the running game.
- Record reviewer, rollback, and all results in release/acceptance.json.

Current blockers: Unity editor is absent on the implementation machine; physical
controller/gameplay acceptance has not run. Stage/main contain only baseline
documentation and promotion controls until a qualified candidate is available.
