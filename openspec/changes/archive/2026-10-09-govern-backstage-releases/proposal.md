# Proposal

## Why
The user requires a stable main branch, a develop/stage promotion path, a canonical
meta planning branch, and agent judgment grounded in the full venue product model.

## What Changes
- Canonical specs move to meta with preserved business intent and decision history.
- Every branch receives a universal README pointing to meta.
- Promotions enforce develop -> stage -> main, checks, and release evidence.
- Agent rules require reasoned pushback on poor code, UX, and unsupported assumptions.

## Capabilities
### New Capabilities
- `release-promotion`: Verified branch promotion and stable main.
### Modified Capabilities
- `repository-boundaries`: Meta planning and develop/stage/main roles replace initial empty-main setup.
- `agent-governance`: Business context and critical engineering/design judgment.

## Impact
Specs governance, business docs, adapters, READMEs, and code-side promotion checks.
Game integration and hardware verification remain in integrate-backstage-foundation.
